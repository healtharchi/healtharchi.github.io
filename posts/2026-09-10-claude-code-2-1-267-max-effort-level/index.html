Claude Code 2.1.267: effort上限設定

Claude Code v2.1.267が公開。全プロバイダのeffort上限を設定するmaxEffortLevelと、システムプロンプトを毎回再生成するオプションが追加され、管理設定やセッション再開の不具合も修正されました。

何が発表されたか

Anthropic は 2026年9月9日、Claude Code v2.1.267 を GitHub のリリースとして公開しました。今回の追加機能は「effort の上限管理」と「システムプロンプトの反復調整」の 2 つの用途に関わります。前者には新設定 maxEffortLevel、後者には起動オプション --system-prompt-snapshot off を使います。上限管理は Bedrock・Vertex・Foundry を含む全プロバイダが対象で、利用者側は上限より低い effort を選べる設計です。

このほか、管理設定 allowedHttpHookUrls・httpHookAllowedEnvVars・allowedChannelPlugins が読み取れない場合に「すべて許可」ではなく「何も許可しない」扱いになる修正、5 MB を超えるセッションの再開時に並列ツール呼び出しとフック出力が失われる問題の修正、サンドボックスを必須とする管理設定の組織でクラウド上の Cowork 定期タスクが起動時に失敗する問題の修正などが含まれます。

誰に関係するか

  • 開発者: Claude Code を日常的に使う人。プロンプト調整中なら新オプションが役立ちます。
  • 企業のIT部門: Bedrock・Vertex・Foundry 経由で Claude Code を利用している組織。maxEffortLevel で、全体またはモデル別に effort の上限を設定できます。
  • プロンプト文を調整する利用者: リクエストごとにシステムプロンプトを再生成する新オプションが関係します。

今日できること

  • Claude Code を v2.1.267 に更新し、GitHub のリリースページで変更点を確認する。
  • 組織で effort を制限したい場合、settings に maxEffortLevel を追加する。モデル別に変えるなら modelSettings 配下に置く。
  • システムプロンプトを調整中なら --system-prompt-snapshot off を付けて起動し、毎回のリクエストで最新のプロンプト文が使われることを確認する。

注意点

  • 日本からの利用可否や地域制限について、リリースノートに記載はありません（出典に記載なし）。
  • effort 上限の既定値や、上限を超える指定をした場合の挙動は、リリースノートに書かれていません（出典に記載なし）。
