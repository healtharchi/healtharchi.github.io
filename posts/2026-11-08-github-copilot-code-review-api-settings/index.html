Copilot code review設定をAPIで管理可能に

GitHubはCopilot code reviewの設定をREST・GraphQL APIで管理できるようにしました。レビュー概要の簡素化と不具合修正も含み、組織管理者と開発者に関係します。

対象:GitHubの組織管理者開発者企業のIT部門

何が発表されたか

GitHubは2026-11-06、Copilot code review（Copilotによるプルリクエストの自動レビュー）の更新を公開しました。対象はCopilot Pro、Pro+、Max、Business、Enterpriseの各プランです。変更点を目的別にまとめます。

  • 設定の一括管理: REST APIとGraphQL APIで、enterpriseのポリシーから個々のリポジトリまで、レビュー設定を読み書きできます。役割ごとに触れる範囲が分かれます。
    • Enterprise管理者: 全organizationで有効・無効を決めるか、organization側に任せる
    • Organization管理者: 有効化、既定のレビューeffort、runner設定。enterpriseが決めた設定は上書きできません
    • Repository管理者: レビューeffortと、custom instructionsやMCP toolsを使うかどうか
  • 出力の追跡: APIでCopilotのレビューとコメントを帰属フィールドで見分けられます。Copilotがコメントの参照元として報告したskills、MCP servers、custom instructionsも確認できます。
  • 画面の整理: レビュー概要は指摘を上にまとめ、レビューしなかったファイルをFiles not reviewed 欄に集約します。
  • 費用と運用: code review agentのセッションに、消費したAI creditsが表示されます。失敗やタイムアウトしたレビューは自動で一度だけ再試行されます。

誰に関係するか

  • GitHubの組織管理者: 多数のリポジトリの設定を画面で一つずつ変える手間が減ります。ただし、enterpriseとorganizationの設定エンドポイントは、GitHub Appsとfine-grained personal access tokensに対応していません。
  • 開発者: 自動化の仕組みでCopilotのコメントを人のコメントと分けて扱えます。リポジトリ設定のエンドポイントは、GitHub Appとfine-grainedトークンの両方で使えます。
  • 一般利用者: Copilot code reviewを使っていなければ、影響は小さいです。

今日できること

  • GitHubのConfiguring Copilot code review with the APIを開き、自分の役割で触れる設定を確認する。
  • リポジトリ設定を自動化するGitHub Appやfine-grainedトークンには、読み取りにAdministration: read、更新にAdministration: writeを付ける。classic personal access tokenはリポジトリ管理者権限が必要です。
  • 自動レビューが不要な人や仕組みがあれば、リポジトリルールAutomatically request Copilot code reviewのbypass listに入れる。
  • code review agentのセッションで、レビューごとのAI credits消費を確認する。

注意点

  • 料金そのものの変更は出典に記載なしです。
  • REST APIで扱えるレビューeffortの段階は、Web画面と同じとされています。出典にはBalanced effortへの言及がありますが、利用可能な段階の全一覧は記載されていません。
