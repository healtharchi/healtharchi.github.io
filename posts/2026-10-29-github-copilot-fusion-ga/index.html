GitHub Copilot Fusionが一般提供に

GitHubは、タスクごとに使うモデルを自動で振り分けるCopilot Fusionを、全Copilotプランで一般提供しました。開発者は努力レベルを選ぶだけで済み、管理者は使えるモデルと既定設定を制御できます。

対象:開発者企業のIT部門開発組織の予算管理者

○
判定: 試す価値あり

何が発表されたか

GitHubは2026年10月28日、GitHub Copilot Fusionの一般提供（GA）を発表しました。作業のたびにモデルを選ぶ代わりに、Copilotが使うモデルを自動で振り分け、必要に応じて複数のモデルを組み合わせる仕組みです。研究プレビューだったProject HydraFusionの複数モデル連携と、Copilotの自動モデル選択を一つにまとめたものです。

利用者が選ぶのはモデルではなく「努力レベル」です。

  • Fusion Standard: 日常のコーディング向け
  • Fusion High: 難しい作業や深い推論向け
  • Fusion Max: 最も要求の高い作業や複雑な推論向け

モデルの組み合わせ方は、単一のモデルで直接解く「Single」、軽いモデルの下書きを品質確認して必要なら上位モデルに引き上げる「Cascade」、別のモデルがレビューして元のモデルが直す「Critique」があります。

提供条件と費用は次のとおりです（出典に記載の時点）。

  • 対応環境: Visual Studio Code、GitHub Copilot app、GitHub Copilot CLI、JetBrains IDEs。その他のクライアントは近日対応予定
  • 課金: Fusionが使った各モデルの標準料金。期間限定で、有料Copilotプランの利用者はモデル費用が30%割引（終了日は出典に記載なし）
  • 性能（GitHub自身の発表）: Artificial Analysis Coding Agent IndexでFusion Maxは60点。Claude Code with Opus 5.5 Maxに近い水準で、タスクあたりのAPIコストとトークン数は約半分、所要時間は約40%短かったとしています

誰に関係するか

  • 開発者: 作業の途中でモデルを切り替える手間がなくなります。重い作業の後に高いモデルのまま日常作業を続けてしまう、といった無駄を減らせる可能性があります（推測）。
  • 企業のIT部門・Copilot管理者: Fusionは、エンタープライズと組織のモデルポリシーで有効なモデルだけを使います。全員向けには残したまま、Fusion用だけ特定のモデルを外すこともできます。
  • 開発組織の予算管理者: 料金は定額ではなく、使われたモデルごとに積み上がります。30%割引は期間限定なので、割引のない状態の費用も見ておく必要があります。
  • 一般利用者: 影響は小さいです。

今日できること

  • クライアントを更新し、モデルピッカーで Copilot Fusion を選んで、努力レベル（Standard / High / Max）を選ぶ。まずは普段の作業をStandardで試す。
  • 管理者は、エンタープライズ／組織のモデルポリシーで、Fusionが選ぶ候補モデルを確認する。費用や社内規定で外したいモデルは、Fusion用だけ無効化する。
  • 管理者は Enterprise managed settings で、Copilot Fusionを利用者の既定モデルにするかを検討する。既定にする場合、どの努力レベルにするかも決める。
  • 研究プレビューで auto、HydraFusion、HydraFusion Max を使っていた人は、選択が対応する努力レベルに自動で移っているかを確かめる。

注意点

  • 日本での提供条件は出典に記載なしです。
  • 性能の数字は、GitHubが示した特定の指標（Artificial Analysis Coding Agent Index）の結果です。自社の作業で同じ結果になるとは限りません。
  • 30%割引の対象は有料Copilotプランの利用者で、期間限定です。
