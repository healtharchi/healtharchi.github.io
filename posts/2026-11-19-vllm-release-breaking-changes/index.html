vLLM v0.34.0、Model Runner V1を削除

vLLM v0.34.0 が公開されました。Model Runner V1 の削除、既定ブロックサイズの変更、ROCm 7.2 向け配布の終了など既存の構成に響く変更があり、vLLM で推論サーバーを運用する人は更新前の確認が必要です。

何が発表されたか

vLLM project が vLLM v0.34.0 を公開しました。GitHub のリリースページでは 16 Nov の公開、Latest と表示されています。412人のコントリビューターによる1,061コミットを含みます。

  • Extensible KV cache が既定で有効になりました。ウォームアップ後に実際に空いているメモリから cache の大きさを決めます。
  • Model Runner V1 は削除されました。Model Runner V2 が唯一の GPU ランナーです。
  • 既定のブロックサイズが64になりました。
  • ROCm 7.2 向けの配布は終わりました。ROCm 10.0 の wheel とイメージを使います。
  • huggingface_hub >= 2.0.0 が必須になりました。
  • Mistral Large 4、MiniMax-M3.1-Flash、Nemotron-3.5-Transcribe など、10個の新しいモデルに対応しました。

誰に関係するか

  • vLLM で推論サーバーを運用する開発者・MLエンジニア: VLLM_USE_V2_MODEL_RUNNER=0 を残したままだと、起動時に失敗します。gpu_memory_utilization は、多くの場合は設定しないのがよいとされています。
  • GPU 基盤の運用担当: cache が増えた例として、H200 上の MiniMax-M3 で 433k から 672k トークンになったと書かれています。一方、一部のモデルではトークンあたりのデコード遅延が上がることがあります（concurrency 128 の一部の H200 モデルで TPOT +6–18%）。
  • AMD ROCm 環境の利用者: -rocm72 はもう公開されません。ROCm 10.0 の wheel とイメージへ切り替える必要があります。

今日できること

更新する前に、自分の構成を次の4点で確かめます。

  • 起動の設定に VLLM_USE_V2_MODEL_RUNNER=0 があれば削除する。
  • gpu_memory_utilization の指定を外せるか確認する。GPU を他のプロセスと共有する場合や、extensible KV cache を無効にする場合は残す。
  • 従来の動作を保ちたい場合は –block-size 16 を渡す。
  • 依存を huggingface_hub >= 2.0.0、tokenizers >= 0.23.3、timm >= 1.0.30 に上げる。ROCm 7.2 の環境は ROCm 10.0 の wheel とイメージに切り替える。

注意点

  • Extensible KV cache をやめたい場合は、–gpu-memory-utilization 0.9 または –no-enable-extensible-kv-cache を使います。
  • Marlin W4A8 は削除されました。代わりに –quantization humming と VLLM_HUMMING_INPUT_QUANT_CONFIG を使います。
  • 高速化の数値は、特定のモデルとハードウェアの組み合わせでの値です。最大1.95×のデコードは、GB200 上の Step5 の値として書かれています。
  • 料金と、日本からの利用可否は、出典に記載なしです。
