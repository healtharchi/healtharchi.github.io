AWS、Claude向けEFS・EDCをプレビュー

AWS が Amazon Bedrock で、モデル提供元の制度を探して登録する API を一般提供し、Claude 向けの EFS と EDC をパブリックプレビューとして公開しました。保持データの置き場所を選べます。

対象:企業のIT部門セキュリティ・コンプライアンス担当開発者

何が発表されたか

AWS は 2026年11月23日、Amazon Bedrock の trusted access program API の一般提供を発表しました。trusted access program は、提供元の定める条件を受け入れることで、安全審査の扱いやモデルの機能へのアクセスをより細かく決められる、提供元の名前つきの制度です。この API を使うと、自分のアカウント、AWS Organizations の組織、または Amazon Bedrock のプロジェクトについて、利用できる制度とその状態を一か所で調べられます。

あわせて、Claude モデル向けの最初の2つの制度 Enterprise Frontier Safeguards（EFS）と Enterprise Data Controls（EDC）がパブリックプレビューとして公開されました。対象には Claude Fable、Claude Mythos、および Cyber Verification Program（CVP）経由で使う Claude Opus 5.5 と Sonnet 5.5 が含まれます。EFS では入力と出力が顧客自身の AWS アカウント内にとどまります。EDC は同じ自動の安全監視を行いますが、保持データは AWS 管理キーで暗号化された Amazon 管理ストレージに置かれるため、バケットやキーの用意が要りません。

誰に関係するか

  • 企業のIT部門: 誰が制度に登録できるかを、既存の IAM ポリシーとサービスコントロールポリシー（SCP）で決められます。登録はいつでも取りやめられます。
  • セキュリティ・コンプライアンス担当: EFS では AWS の人間のレビュアーが内容を確認せず、AWS と Anthropic のどちらの人間も保持された入力と出力にアクセスせず、学習にも使われないと説明されています。自動の安全監視がリスクを見つけると Case が作られ、確認するのは顧客のチームです。
  • Amazon Bedrock で Claude を使う開発者: 推論の呼び出し方そのものは他の Amazon Bedrock のモデルと同じです。EFS の Case の確認では、violation か no_violation を記した回答ファイルを review-responses/ に書きます。EDC ではパブリックプレビュー中は Case が届きません。

今日できること

  • trusted access program API で、自分のアカウント・組織・プロジェクトについて制度の一覧と状態を確認する（状態は eligible なら登録でき、requestable なら先に資格の承認が必要）
  • requestable だった場合は、応答の statusReason フィールドに書かれた方法で資格の承認を申請する
  • プレビューはすでに EFS ZDR に登録している顧客が対象で、申請は AWS のアカウントチーム経由で行う
  • 社内の方針が保持データを自社の保管先に置くことを求めるなら EFS、Amazon 管理ストレージと AWS 管理キーで良いなら EDC を選ぶ。ストレージ設定はリージョンごとに必要で、設定の無いリージョンでは Amazon 管理ストレージが使われる

注意点

  • EFS と EDC はパブリックプレビューです。日本のリージョンについての記載は出典にありません。
  • プレビューに参加すると、追加したアカウントでは暫定の ZDR 例外が無効になります。
  • EFS でキーやバケットへのアクセスを外すこと自体はいつでもできますが、Amazon Bedrock はアクセスを失ってから24時間後に対象モデルの提供を止めます。
  • Claude Fable モデルを EFS・EDC 以外の aws_review データ保持モードで使う場合、Amazon Bedrock が入力と出力を最大30日保持します。対象の顧客は現行の Fable モデルを社内利用に限りデータ保持ゼロ（ZDR）で少なくとも2027年6月30日まで使え、EFS はこの暫定措置が終わった後の長期的な道筋とされています。
