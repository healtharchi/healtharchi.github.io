Copilot HydraFusion、VS Codeにも拡大

GitHubは複数モデルを組み合わせるHydraFusion（research preview）をVS Codeとアプリに拡大。対象はCopilot Pro／Pro+／Business／Enterpriseで、組織では管理者の有効化が必要。

対象:開発者企業のIT部門

何が発表されたか

GitHub は 2026年9月30日付の Changelog で、HydraFusion の research preview（研究段階の試験提供）を Visual Studio Code と GitHub Copilot app でも使えるようにしたと発表しました。これまでは Copilot CLI だけが対象でした。

HydraFusion はモデルピッカー（使うAIモデルを選ぶメニュー）に並びますが、単一のモデルではありません。推論・コード生成・デバッグ・ツール利用の能力シグナルをもとに、品質基準を満たす効率的な進め方を次の 3 つから 1 つ選びます。

  • Single: 選ばれた 1 つのモデルがそのまま解く
  • Cascade: 効率的なモデルが下書きし、品質ゲートが採用か、より強いモデルへの引き上げかを決める
  • Critique: 下書きを別モデルファミリーの読み取り専用の批評役が確認し、元のモデルが 1 回だけ修正する

既存の Auto はリクエストごとにモデルを選ぶ機能です。HydraFusion は 1 ターンの中で進め方の選択と複数モデルの連携まで行う点が異なります。

今回は提供面の拡大に加え、各段階で何をしているかの表示、進捗更新の頻度、長いタスク中の状態表示も改善されました。

提供条件は次のとおりです（出典に記載の時点）。

  • 対象: Copilot Pro、Pro+、Business、Enterprise の利用者
  • Business と Enterprise: 管理者がプレビュー機能を有効にする必要あり
  • VS Code: version 1.140 以降、または VS Code Insiders
  • 位置づけ: 引き続き research preview で、変更の可能性あり
  • 料金・利用枠の消費: 出典に記載なし

誰に関係するか

  • 開発者（Copilot Pro／Pro+ の個人利用者）: 普段の VS Code やアプリのチャットで、1 つのモデルに任せる方式と複数モデルを組み合わせる方式を比べられます。
  • 企業のIT部門（Copilot Business／Enterprise の管理者）: 管理者がプレビュー機能を有効にしない限り、社員の画面には出ない可能性があります。試験導入を認めるかどうかの判断が必要です。
  • Copilot を使っていない人: 影響は小さいです。

今日できること

  • VS Code を version 1.140 以降（または VS Code Insiders）に更新し、Copilot Chat のモデルピッカーで HydraFusion を選ぶ。表示されなければ設定 chat.copilot.hydraFusion.enabled を有効にする。
  • GitHub Copilot app を最新版に更新し、Settings で「HydraFusion」を検索してオンにしてから、モデルピッカーで選ぶ。
  • Business／Enterprise の管理者は、組織または企業の設定でプレビュー機能を有効にするかを決める。research preview で仕様が変わり得る点を社内に伝えておく。

注意点

  • research preview のため、ワークフローの種類や挙動は今後変わる可能性があります。
  • 料金や利用枠への影響、日本での提供条件は出典に記載がありません。性能の数値も出典本文にはありません。
