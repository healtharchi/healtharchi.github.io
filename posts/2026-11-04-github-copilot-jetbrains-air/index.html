GitHub CopilotがJetBrains Airに対応

JetBrains AirでGitHub Copilotにコーディングを任せられるようになりました。IDE内でもAir Teams経由のクラウドでも動き、クラウド分はCopilotのプランを使います。開発者と管理者向けです。

対象:開発者企業のIT部門

何が発表されたか

GitHub は 2026-11-03 の Changelog で、JetBrains Air から GitHub Copilot を呼び出せるようになったと発表しました。Air の上で、Copilot にコーディングタスクを任せ、途中で方向を指示し、結果をレビューできます。

  • つなぎ方: Agent Client Protocol (ACP) を使った連携です。
  • 動く場所: JetBrains IDE の中（ローカル）と、クラウドの両方に対応します。
  • 使い方の変化: Air のエージェント選択で GitHub Copilot を選ぶと、既存の Copilot サブスクリプションで動きます。複数のエージェントセッションを並行して追い、コードの横で変更を確認できます。
  • クラウドの実行環境: 新しい仮想マシン上の Docker コンテナで動き、通信はすべてプロキシ経由です。タスク間で状態は残りません。
  • 支払い: クラウドタスクは JetBrains AI のクレジットではなく、Copilot のプランを使います。

従来の GitHub Copilot プラグインと並べて使い、作業に合う方を選べるとされています。

誰に関係するか

  • 開発者: JetBrains IDE を使っていて Copilot も契約している人は、既存の Copilot サブスクリプションを使って Air からコーディングタスクを実行できます。
  • 企業のIT部門・開発組織の管理者: クラウドタスクを許可するかどうかを決める立場になります。Air の管理者はガバナンスポリシーで Copilot を無効にできます。一方で、Air 内で Copilot の支出上限は設定できません。Air のガバナンス・分析機能にも Copilot の利用状況は含まれません。
  • 一般利用者: 影響は小さいです。

今日できること

  • 手元で試す: JetBrains IDE に Air を入れ、エージェント選択で GitHub Copilot を選び、Copilot アカウントを接続します。
  • クラウドで試す（企業）: Air Teams が有効な企業組織の JetBrains アカウントと Copilot サブスクリプションを用意し、Air 管理者に Copilot を有効化してもらいます。ブラウザ版 Air では Settings > VCS Providers で GitHub を接続し、タスクを作り、リポジトリとリモートブランチを選んで GitHub Copilot を選び、プロンプトを送ります。IDE からは環境選択で Cloud を選びます。
  • 費用の管理方法を先に決める（管理者）: Air 側では Copilot の利用状況が見えず、支出上限も設定できません。Copilot の利用状況を把握する方法を別途確認し、運用ルールを決めておきます。

注意点

  • 個々のタスクで、個人の Copilot プランと組織のプランのどちらを使うかは選べません。
  • サブスクリプションやクレジットの確認は、クラウド環境の起動時に行われることがあります。使えない状態だとタスクが失敗し、セッションにエラーが表示されます。
  • 日本からの利用可否と提供地域は出典に記載なしです。ここでの内容は 2026-11-03 の発表時点のものです。
